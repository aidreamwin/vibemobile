# 已知限制

这些是当前实现承认的边界，不是待办清单的重复。改动相关代码前请先读
[CLAUDE.md](../CLAUDE.md) 里对应的约束。

## 权限与安全

- **新建会话时选的沙箱不起作用。** 真正决定每回合沙箱和审批的是输入框上那个
  权限项，它**每回合覆盖**建会话时的预设。建会话时选只读、直接发消息，实际
  生效的是「按需确认」。要用只读，得先把输入框那一项拨过去。
- **新建会话的 9 种 `(sandbox, approvalPolicy)` 组合里，有 6 种在输入框上
  表达不出来。** 输入框只有固定的几张卡（Claude 4 张、Codex 3 张）。这种会话
  会被记住，但下次打开时权限项停在「按需确认」；用户一发消息，机器就按屏幕上
  那张卡被驱动。保证成立的只有两条：认不出的组合绝不会点亮完全访问；屏幕上
  那一档就是下一回合发出去的那一对。
- **「自动判断」是 Claude 专属，且不向手机抛审批。** 实测 `canUseTool` 被调用
  0 次，工作区内外的写/删都会执行；分类器判不了时**直接拦掉动作**，手机上看
  不出它放过了什么。它也不能在建会话时选，只能在输入框里切换。
- **「完全访问」在两个后端都等同于无人值守。** 手机点一下之后不再有任何确认。
  这是本应用里唯一能让一部手机拿到无限制机器权限的入口 —— 暴露到公网前请
  三思，见 [SECURITY.md](../SECURITY.md)。
- **单用户设计**，没有多用户、角色、ACL 或配额。

## 代理与会话

- **Claude 检测不到并发写入者。** Codex 有「该会话已有活跃写入者」的错误；
  Claude 没有对应物，只能防止本服务重复 attach。`Chat.tsx` 的「会话被占用」
  只读态对 Claude 永远不会触发。
- **Codex 的 `request_user_input` 只验证了一半。** 代码侧已经映射
  `questions` / `answers`，但「什么时候触发、app-server 收到响应后做什么」还
  没有跑过真实链路。依赖它之前先起一次 app-server 实测。
- **新建但一条消息都没发过的 Codex 会话，服务重启后就找不回来。** app-server
  的 thread 只有跑过回合才有 rollout；这类线程在创建它的 app-server 进程存活
  时读得到，进程一换就变成 `no rollout found`。请求会返回 404，前端把
  `DELETE` 的 404 当成成功。
- **Codex 的协议措辞会随版本变化。** `thread not loaded` /
  `no rollout found` / `is not materialized yet` 都只能按文案识别，升级 Codex
  时必须逐条重新验证。

## 转写与媒体

- **图片缓存不跟随会话删除，也没有容量上限。** `.vibemobile/images/` 是纯
  缓存，整个删掉永远安全；下一次读转写会从代理自己的会话文件里重建。
- **图片真的取不到时缩略图会隐藏**（`onError`），不显示裂图。
- **Claude 的 `getTranscript` 找到会话 JSONL 就整份读。** 大会话第一次打开
  需要更多时间；读取器按 512 KB 窗口从文件尾反向倍增，成本与返回的历史成
  正比，但一次全量读取仍可能达到百毫秒级。
- **Claude 的 `c:<轮数>` 游标在翻页期间有新回合时会漂移。** 前端按 item id
  去重兜底。
- **Codex 的会话列表搜索只匹配标题，不匹配对话正文。** Claude 侧是在已拿到的
  会话信息上做子串匹配。
- **Claude 的自动压缩由本服务显式开启，并按上一回合的
  `modelUsage.contextWindow` 留 20% 余量。** 这是为了覆盖代理模型（例如
  `deepseek-flash[1m]`）未被 CLI 目录完全识别、默认压缩边界不可靠的情况。
  观察不到窗口时，首回合用模型名里的 `[1m]` 标记推断；两者都没有时仍使用
  CLI 自己的策略。一次已经开始的、工具输出巨大的回合仍可能在中途触顶，
  此时需要手动发送 `/compact`。

## 前端与设备

- **UI 目前只有中文。** `index.html` 的 `lang` 是 `zh-CN`，PWA manifest 也是
  中文；没有 i18n 机制。欢迎单独贡献国际化。
- **语音输入、Diff 查看尚未在真实浏览器中全面验证**；未在真机 iOS Safari /
  Android Chrome 上测试过。语音输入依赖 Web Speech API，目前只有 Android
  Chrome 可用。
- **`smoke:browser` 依赖无头 Edge 和 Radix 的 pointer-type 初值**；改 Radix
  select 版本时需要重新验证审批环节。

## 部署与运维

- **前后端 dist 在部署时会不同步。** 前端按请求读磁盘，后端在进程启动时载入；
  改了 `/api` 契约必须重建后端并重启服务。
- **服务重启比看起来慢。** NSSM 的停止超时是 15 秒；`Restart-Service -Force`
  可能报错，使用 `Stop-Service -Force` → 轮询到 `Stopped` → `Start-Service`。
- **`MAX_ENTRIES = 500` 的会话存档淘汰会静默取消归档 / 取消置顶。** 被挤出的
  老会话会重新出现在列表里，图钉消失。
- **多 runner 的跨机器会话聚合、离线历史缓存、一次性配对码、凭据在线吊销、
  执行幂等账本、事件补发等尚未实现。** 见 [multi-runner.md](multi-runner.md)
  的后续范围。
